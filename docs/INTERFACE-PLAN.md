## 验收清单
- 布局：默认窗口与最小窗口可用，活动栏和侧栏关系清楚，输入区可编辑保存；长名称/路径不挤走操作。
- 工作面：辅助面可打开/关闭，标签切换有明确选中状态，切换不影响草稿；未接入终端/差异/视频明确显示未接入。
- 设置：独立分组可导航；本地外观偏好真实改变界面并按约定恢复；服务配置显示未接入，不保存假凭据。
- 材质：导航/控制层轻玻璃，内容实底；降低透明度和不支持模糊时仍可读；减少动画或系统偏好生效。
- 键盘：关键按钮、会话、输入、标签、设置均可达；焦点可见、图标有名称、浮层可退出；保留 Ctrl+S。
- 数据回归：创建/切换/重命名/编辑/保存/重启恢复；失败不覆盖数据，未保存草稿保护不退化。
- 边界：原有五个桌面 API 不变，renderer 不新增系统执行或供应商访问；无桌面桥行为诚实，偏好不是权限。
- 证据：执行 typecheck、build、目标存储与真实 Electron 检查；保存默认、窄窗口、设置和辅助面的截图并目视；独立 Agent 对实际代码及适用检查复核。

每项结果区分真实桌面、测试替身、浏览器预览和未验证。具体命令/日志/截图路径由主 Agent 记录到验收和变更文档，不在多份规范复制日志。

## 执行检查点

1. 按 UI-001-INTERFACE-SCOPE 登记所有权：主 Agent 负责依赖及验证，ui_builder 负责 src，spec_writer 只写 FRONTEND-RULES 与本计划，最终文档和独立审查另行交接；禁止交叉覆盖。
2. 保持 Electron/React/TypeScript/Vite；采用锁定的 radix-ui 1.6.7 与 @radix-ui/react-icons 1.3.2，许可证已核实 MIT。仅将确实使用的交互原语接入基础组件。
3. 先落地 tokens/base/layout/components 与 styles.css 导入入口，再组装实际组件。检查新组件不引入硬编码第二套主题；原入口保留明确职责。
4. 实现侧栏、主区、草稿编辑和按需辅助面，逐项保留原五 API、本地会话数据及失败保护。设置仅保存 ui.preferences.v1 三个呈现字段，校验损坏数据与存储失败，响应系统偏好。
5. 把静态中文文案集中至 i18n/zh-CN.ts；检查长标题、路径、操作名称与错误。全局交互统一，不给未接入能力制作可误解的执行控件。
6. 主 Agent 更新适用的真实桌面检查，运行 npm.cmd run typecheck、npm.cmd run build、npm.cmd test、npm.cmd run test:desktop。记录本轮证据，必要时区分真实 preload 与测试对话框替身。
7. 批量检查默认1360×900、最小960×640、设置、辅助面、主题、减少透明度/动画和关键错误截图；实际目视与键盘检查。按 impeccable 做一轮集中修正及最多一轮确认，不无限微调。
8. 非实现 Agent 独立读取实际代码并运行适用检查；fresh finish reviewer 不继承实现历史。只有本轮证据支持的项才能标通过，影响使用问题修复复核后再交付。
9. 用实际文件、组件与验证状态收尾规则和 DESIGN/PRODUCT，更新 HANDOFF/TASKS/BUGS/CHANGES。交付可审阅候选；用户确认才冻结，安装包及外部接入不计完成。

## 交接与变更控制
本次必要拆分不改变 Electron/shared 的信任边界，不引入第二套 Agent、样式或状态框架，不删除原入口文件；保留的兼容入口必须有明确职责。新依赖由主 Agent 按实际用途与许可证核实并维护锁文件。

影响使用的问题在本轮修复并验证；无影响 P3 在 BUGS 登记冻结。若参考、实现和规则冲突，先记录并协调最小修正，不虚构完成。技术栈、结构和界面一起供用户确认；用户确认后记录精确基线，后续改变冻结范围须先说明影响并获批准。
